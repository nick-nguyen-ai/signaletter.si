    tags:
    - Cline

    sources:
    - GitHub releases
    verdict: Worth reading
    what_changed: Cline CLI 3.0.75 (21 Nov) starts one-shot runs (a prompt argument or piped stdin) in yolo mode instead of act mode, because nobody is at the keyboard to approve tools. Act mode is kept if auto-approve is off (--auto-approve false or the saved setting), a mode flag is passed, plan mode is saved, or the prompt is a /team prompt. --timeout and Ctrl+C can now stop the first turn, and the CLI no longer reads .env or bunfig.toml from its launch folder. In the VS Code extension 4.1.27 and the CLI, read_files results now reach the model in full up to 2,000 lines or about 48k characters, and the MCP (Model Context Protocol) tab badges tools whose server declares them read-only.
    why_it_matters: If any scripts or CI jobs call Cline non-interactively, tool calls that used to wait for approval will now run unattended unless you pin --auto-approve false or a mode flag.
    caveats: Yolo mode has no team tools; pass --act when you need them. The default model for the Cline provider with no saved choice is now the first free model, not Claude Sonnet 5.5.
    how_to_try: Add --auto-approve false (or --act) to any scripted cline call, then rerun one job to confirm approvals behave as expected.
