    tags:
    - Responses API

    sources:
    - OpenAI docs
    - X (OpenAIDevs)
    verdict: Worth reading
    what_changed: OpenAI's new 'Keep the prefix unchanged' guide, announced on 20 Nov (Sydney time), says that, starting with newer frontier models, the API drops reasoning items that follow a change to earlier conversation history, as part of OpenAI's safeguards. If you shorten a tool result, rewrite a developer message or replace older turns with a summary, those reasoning items are dropped, and the model may have to redo that reasoning at extra cost and latency. OpenAI recommends an append-only pattern and keeping reusable instructions stable; changes to reasoning effort, output schema or tools can be appended as configuration_update or additional_tools items instead.
    why_it_matters: Context-trimming and custom summarising middleware, common in LangGraph and custom harnesses, now has a cost on GPT-6.2; the guide's Prompt Cache Diagnostics and input_transformations show whether your agents rewrite history mid-run.
    caveats: The guide describes this as a safeguard, so it is not optional. OpenAI's own compaction (/responses/compact or context_management) keeps the reasoning items that follow; custom compaction should put the compacted item at the end of the context. OpenAI gives no figures for the quality drop.
