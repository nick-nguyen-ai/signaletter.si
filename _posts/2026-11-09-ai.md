    headline: Claude Code's “don't ask again” file exposed secrets in 1,122 public GitHub copies
    takeaway: Approving an exact command saves it word-for-word in .claude/settings.local.json; Apiiro found 1,379 distinct secrets in those public files.
    tags:
    - Claude Code
    - Secrets
    - GitHub
    sources:
    - The Hacker News
    - Anthropic
    verdict: Worth trying
    what_changed: The Hacker News reported on 7 November that Apiiro searched public GitHub for Claude Code's project-local settings file. It found 104,185 copies of .claude/settings.local.json in 103,617 repositories; 1,122 of them (about 1.1%) held at least one secret, together 1,379 distinct secrets. A broader total including git history, shared .claude/settings.json and saved chat logs is 2,539 secrets across 1,994 repositories. Breakdown of the current-file secrets includes 379 database passwords, 43 SSH logins for public servers, 42 GitHub/GitLab/npm tokens and 23 AWS keys, across owners at 63 organisations. In 539 of 1,105 traced repositories, a Claude-coauthored commit changed the file. Older versions hid 734 further secrets across 509 repositories, and 211 forks of 74 repositories carried the same secrets. Secrets also sat in 298 of 76,011 copies of the shared .claude/settings.json. Of the 1,122 secret-bearing local files, gitleaks flagged 564 and TruffleHog 643; neither flagged
      215, mostly passwords typed inside commands. Apiiro compared documentation for 16 coding agents and said Claude Code is the only one confirmed to save the full approved command in a project file by default. Anthropic's settings docs confirm that “Yes, and don't ask again” writes an allow rule to .claude/settings.local.json and that Claude Code adds **/.claude/settings.local.json to the user's global git excludes the first time it writes the file — protection that stays on that computer and does not add the path to the project's .gitignore. One notified company confirmed its key had been live; Apiiro did not test whether secrets still work. A bug report filed 11 August 2025 was closed “not planned” on 3 January after 60 days without activity; The Hacker News said four related reports had been closed by the same bot.
    why_it_matters: You run Claude Code daily, and a bank laptop or shared checkout that once approved a command containing a password, token or connection string may have committed that exact command. Org-wide search plus rotation beats scanner defaults, which missed many of these passwords.
    caveats: The Hacker News dated 7 November; Apiiro did not test whether the secrets still authenticate. Global git excludes protect new writes on one machine, not files already committed, created by hand, or copied into images and packages.
    how_to_try: Search your GitHub organisation and every repo's git history for .claude/settings.local.json and .claude/settings.json. Rotate every password, token and key those files have ever held before cleanup. Then git rm --cached .claude/settings.local.json, add it to the project's .gitignore, delete any local allow rule that contains a secret, prefer pattern approvals such as Bash(npm run:*), and pass secrets as environment variables rather than literals.

    headline: Anthropic maps agent memory into transcripts, notes, wikis and injected context
    takeaway: On a ~350,000-file Stainless codebase, a learned wiki lifted a 25-question score from 13% to 48% over 128 sessions; search plus wiki saved about 20,000 tokens per question versus search alone.
    tags:
    - Memory
    - Claude Code
    - Agents
    sources:
    - Anthropic
    verdict: Worth reading
    what_changed: On 6 November Anthropic published “The components of agent memory” by Lance Martin. It describes memory layers including transcripts, notes, representations such as wikis, and injected context, plus “dreaming,” an offline job that consolidates memory outside the live trajectory. In a Stainless corpus of about 350,000 files and about 420 million tokens, a 25-question eval saw the wiki score rise from 13% to 48% over 128 sessions. Search plus wiki scored 54% rising to 61%, against 53% for search alone; wiki alone reached 48%. Anthropic reports that search plus wiki saved about 20,000 tokens per question versus search alone. On the multi-document, judgment-type subset of a 24-question merger set, the wiki scored 87% against 73% for search. In a contract-facts task the agent wrote 41 of 57 facts (72%) correctly into a shared table because later agents overwrote rows in the shared table; assigning one page per contract and refining the instructions in a loop brought it to 57
      of 57. Claude Code injects only the first 200 lines or 25 KB of MEMORY.md as an index. Telling the model to “record only failures” cost Opus 5 and Opus 4.7 much of the memory boost. Anthropic's practical advice is to tell Claude what memory is for, not how to use it.
    why_it_matters: 'This is a concrete blueprint for memory in agentic coding apps you validate: treat MEMORY.md as an index, watch shared-state overwrites, and measure whether “record only failures” quietly deletes the gain you expected from Opus.'
    caveats: Published 6 November (missed by the weekend issue). The Stainless and merger figures (including the subset result) are Anthropic's own evals on their workloads, not a public leaderboard. Do not cite unofficial Opus 5.5 scores that did not appear in this article. The article's layer names are paraphrased here, not an official count.
